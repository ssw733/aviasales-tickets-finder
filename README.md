# Aviasales Pathfinder

Поиск дешёвых связок прямых авиабилетов по данным Travelpayouts.

Rust + Axum + SQLite + Leaflet. Билеты собираются в SQLite, затем загружаются в индексированный RAM-граф, где ищутся кратчайшие пути по цене, времени, пересадкам и датам.

## Возможности

- Все IATA-коды городов и аэропортов из данных Travelpayouts.
- Хранятся только прямые one-way билеты; пути из нескольких сегментов строятся самостоятельно.
- Граф, радиус и результаты привязаны к IATA-кодам аэропортов.
- Поиск: город, страна (несколько стран), радиус на карте, «откуда угодно» / «куда угодно».
- Исключение стран для начальной/конечной точки; пересадки в исключённых странах разрешены.
- До 5 пересадок, ограничение дней на стыковку, окна вылета/прилёта.
- Оптимизация по цене/пересадкам/датам/времени; одна карточка на направление, внутри — варианты по датам.
- Кнопки ведут на Aviasales; для составного маршрута — по сегментам.
- Фоновое обновление: discovery прямых направлений и батчи цен.

## Быстрый старт

```bash
cp .env.example .env
# вставьте TRAVELPAYOUTS_TOKEN в .env
cargo run --release
```

Откройте `http://localhost:8080`.

При первом запуске `airports.json`, `cities.json`, `countries.json` и `routes.dat` скачиваются в `data/`; там же создаётся `data/pathfinder.db`.

## Основные настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TRAVELPAYOUTS_TOKEN` | — | токен Travelpayouts |
| `HOST` / `PORT` | `0.0.0.0` / `8080` | адрес веб-сервера |
| `DB_PATH` | `data/pathfinder.db` | SQLite |
| `DB_HORIZON_DAYS` | `400` | горизонт дат в БД/RAM |
| `DIRECT_PRICE_MARGIN` | `1.0` | насколько дешевле прямого должны быть пересадки |
| `BULK_BATCH_ORIGINS` | `1000` | городов за один батч цен |
| `BULK_HOURS` | `2,8,14,20` | часы запуска батчей |
| `BULK_TZ` | `Europe/Moscow` | таймзона расписания |
| `DISCOVERY_INTERVAL_HOURS` | `12` | период discovery по всем городам |
| `STATIC_RESTART_HOURS` | `24` | перезапуск для обновления статических данных |

Полный список — в `.env.example`.

## Как это работает

1. `prices/direct?origin=CITY` находит прямые направления из города.
2. `prices_for_dates?direct=true&one_way=true` забирает все даты по найденному маршруту.
3. Офферы складываются в SQLite; старые заменяются, мусорные/не-IATA/невозможные по скорости отбрасываются.
4. RAM-граф индексируется по аэропортам: `outgoing`, `by_route`, `destinations_by_origin`, `origins_by_destination`.
5. Поиск ограничен самым дешёвым прямым (для одной точки) и Pareto/beam-отсечением; для регионов ограничение ослаблено, чтобы не терять дешёвые варианты в другие города.

## Автозапуск

`deploy/start.sh` поднимает release-бинарник и перезапускает его при падении. Пример crontab:

```cron
@reboot sleep 30 && /path/to/aviasales/deploy/start.sh >> /path/to/aviasales/data/autostart.log 2>&1
```

## Ограничения

- Travelpayouts отдаёт кэшированные данные; это не полный live-поиск.
- Полный перебор 9653×9653 пар не делается: discovery идёт по всем городам, но цены добираются ротацией батчей.
- Для «откуда угодно» + «куда угодно» показываются самые дешёвые прямые билеты по всей базе; пересадки глобально не могут быть дешевле самого дешёвого прямого.
